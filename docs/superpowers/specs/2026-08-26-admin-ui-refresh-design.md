# 관리자 UI 톤 정비 Design

작성일 2026-08-26 · 브랜치 `design/admin-ui-refresh` (base: `main`)

## 배경

관리자 페이지는 MVP 이후 화면이 네 개까지 늘었지만 스타일은 처음 만든 그대로다. `apps/admin/src/styles.css` 388줄에 색이 hex 로 직접 박혀 있고(`#117a7a` 청록, `#c4542d` 주황, `#f4f7f8` 바탕), 토큰도 재사용 단위도 없다. 화면이 더 늘기 전에 정비한다.

다음 사이클 후보 네 건 중 셋이 화면을 새로 만드는 일이다 — 프로젝트 설정, 프로젝트 전환, 로컬 간편 로그인. 지금 정비하면 그 화면들이 새 체계 위에서 처음부터 지어지고, 미루면 낡은 톤에 맞춰 지은 뒤 두 번 칠하게 된다.

## 목적

시각적 완성도를 올린다. **화면 구성과 흐름은 바꾸지 않는다.** `AppState` 유니온, 상태 전이, 라우팅 방식, 화면 개수 모두 그대로다. 바뀌는 것은 색·타이포·간격과 그것을 담는 구조다.

## 범위

**한다**

- 토큰 계층 신설 (`styles/tokens.css`)
- 프리미티브 5종 신설 (`ui/`)
- 기존 화면 4개 + 상태 화면 4종 재적용
- 차트 2개 재테마 · 반응형 · lazy 분리
- `styles.css` 해체

**하지 않는다**

- 다크 모드
- 밀도 전환 토글
- 새 화면 (프로젝트 설정 · 전환)
- 라우터 도입
- 차트 라이브러리 교체

### 팔레트 근거

레퍼런스는 실제 제품에서 직접 읽었다 (2026-08-26).

- Plausible 라이브 대시보드 — 보더 `#e4e4e7`, 보조 텍스트 `#71717a`, 반경 4–6px. 흰 바탕에 색은 데이터와 액션에만.
- Linear — 본문 15px 에 자간 `-0.011em`, 텍스트 3단 계층.

색은 채도·대비·색각 분리 검증을 거쳤다.

- **기존 브랜드 청록 `#117a7a` 는 채도 0.086 으로 기준(0.1) 미달이다.** 회색으로 읽혀 차트 선이 가라앉는다. 계승하려면 `#0d9488` 급으로 올려야 했고, 최종적으로는 감청으로 교체했다.
- 액센트 후보 중 주황 `#c2410c`(심각과 ΔE 4.8), 핑크 `#be185d`(8.8), 초록 `#15803d`(정상과 11.9)는 상태색을 흉내내므로 탈락했다. **따뜻한 절반은 상태색이 점유한 영역이다.**
- 상태색은 자체적으로 인접 쌍이 가깝다(심각↔정상 CVD ΔE 4.1, 경고↔주의 정상시각 13.6). 색만으로 뜻을 전달하지 않는 것이 완화책이므로 **모든 상태 표시는 점 + 글자를 함께 쓴다.**

## 토큰 계층

`apps/admin/src/styles/tokens.css` 한 파일에 세 층으로 둔다.

**원시값** — 색 스케일, 간격 스케일(2·4·6·8·12·16·24), 타이포 스케일(11·12·13·15·19·22·26px), 반경(4·7·999).

**의미값** — `--surface` · `--surface-sunk` · `--border` · `--ink` · `--ink-muted` · `--ink-faint` · `--accent` · `--accent-soft` · `--status-good|warn|serious|crit`. 컴포넌트는 원시값을 직접 참조하지 않고 이 층만 쓴다.

**밀도** — `--pad`(12px) · `--row-y`(8px) · `--body`(13px) 세 개. 밀도를 바꾸고 싶어지면 이 셋만 갈아끼운다.

`prefers-color-scheme` 블록은 두지 않는다. 의미값 층이 있으므로 나중에 다크를 붙일 때 이 파일만 늘어난다.

## 프리미티브

`apps/admin/src/ui/` 에 다섯 개를 둔다.

| 컴포넌트 | 인터페이스 | 쓰이는 곳 |
| --- | --- | --- |
| `Button` | `variant: "primary" \| "secondary" \| "icon"`, `disabled`, children·`aria-label` 통과 | 버튼 7개 전부 |
| `Chip` | `status: "good" \| "warn" \| "serious" \| "crit"`, `label` **필수** | 이슈 상태, 인사이트 |
| `Card` | `as` 로 태그 지정, 표면·보더·반경 | 지표 타일, 차트 패널, drawer |
| `Field` | `label` · `hint` · `error` | 프로젝트 생성 2필드 |
| `DataTable` | 열 정의를 props 로 | 이슈 목록 |

`Chip` 의 `label` 은 선택이 아니라 필수다. 타입으로 강제해서 색만으로 상태를 전달하는 경우를 원천 차단한다.

`Field` 는 힌트를 `<label>` 밖에 두고 `aria-describedby` 로 잇는다. 힌트를 label 안에 넣으면 접근 가능한 이름에 힌트 문구가 붙어 `getByLabelText("허용 도메인")` 이 실패한다 — 이전 사이클에서 실제로 겪은 결함이므로 프리미티브가 이 구조를 보장한다.

`SessionTimeline` 과 차트 2개는 프리미티브로 만들지 않는다. 재사용처가 하나뿐이라 지금 추상화하면 껍데기만 는다.

## 차트

### recharts 를 유지한다

MVP 구현 계획서가 Tech Stack 한 줄로 recharts 를 지정했고 근거 기록은 없다. 이번에 실측해서 판단했다.

| 빌드 | raw | gzip |
| --- | --- | --- |
| 현재 | 548.44 kB | 158.86 kB |
| 차트 스텁 처리 | 157.05 kB | 50.59 kB |
| recharts + d3 몫 | 391 kB | **108 kB (전체의 68%)** |

Chart.js 4.5.1 은 전체 UMD 기준 208 kB raw / 70.7 kB gzip 이고, line·bar 만 등록하면 45~55 kB gzip 선이다. 즉 교체하면 50~60 kB gzip 을 아낀다.

그럼에도 유지하는 이유는 셋이다.

1. **크기 예산이 걸린 쪽은 SDK 이지 관리자 앱이 아니다.** SDK 는 남의 사이트에서 방문자마다 내려가므로 gzip 10KB 예산을 테스트로 못박아 두었다. 관리자 앱은 운영자가 가끔 여는 내부 화면이다.
2. **canvas 계열로 가면 토큰 체계에 구멍이 난다.** SVG 는 `stroke="var(--accent)"` 가 그대로 먹지만 canvas 는 `getComputedStyle` 로 토큰을 JS 로 복사해와야 한다. 색의 단일 출처가 `tokens.css` 인데 차트만 사본을 들게 된다.
3. **테스트 환경 비용.** `apps/admin/vitest.config.ts` 는 `environment: "jsdom"` 이고 setupFiles 도 canvas 패키지도 없다. jsdom 에는 canvas 2D 컨텍스트가 없어 대시보드를 렌더하는 기존 테스트가 깨지고, canvas mock 을 새로 붙여야 한다.

성능은 판단 근거가 아니다. 지금 그리는 것은 7점 라인 하나와 막대 4개이고, 예정된 사용량 막대·사분면 차트도 수백 점 규모다. canvas 계열의 장점이 나올 자리가 없다.

### 교체 가능성을 유지하는 규칙

나중에 옮길 자유를 남기기 위해 경계를 명시한다.

- 차트는 `apps/admin/src/components/charts/` 아래로 모은다.
- **`recharts` 는 이 폴더 밖에서 import 하지 않는다.** 현재 import 지점은 두 파일뿐이며(합계 33줄) 이 상태를 유지한다.
- 차트 컴포넌트의 props 는 라이브러리 중립적인 순수 데이터만 받는다. 현재도 `{ date, score }[]` 와 `DashboardSummary["issueTypeDistribution"]` 만 받으므로 되돌아가지 않게 지킨다.

린터 설정이 저장소에 없으므로 자동 강제는 하지 않는다. 규칙을 문서에 두고 리뷰에서 잡는다.

### 고치는 것

- `width={420}` 고정 → `ResponsiveContainer`. 지금은 좁은 창에서 잘린다.
- 색을 토큰으로: 선·막대 `--accent`, 격자 `--border`, 축 글자 `--ink-faint`.
- 단일 시리즈이므로 범례를 두지 않는다. 패널 제목이 시리즈를 지칭한다. 선 2px, 끝점 강조, 막대는 상단 반경 4px 에 막대 사이 2px 간격.
- 데이터 0건일 때 빈 차트 대신 문구를 띄운다.
- **`React.lazy` 로 분리한다.** 차트는 대시보드에만 있는데 지금은 로그인·프로젝트 생성·설치 안내 화면에서도 108 kB 를 함께 받는다. 처음 설치하는 사용자가 지나는 경로가 정확히 그 세 화면이다.

## 보존해야 할 접근 가능한 이름

`App.test.tsx` 의 쿼리 28개는 전부 role · label · text 기준이고 클래스나 DOM 구조를 붙잡지 않는다. 따라서 페이지를 전부 다시 써도 아래 이름을 글자 그대로 유지하면 테스트는 살아남는다. **이 목록이 재작성의 계약이다.**

- 버튼 — `Google로 로그인` · `다시 시도` · `로그아웃` · `프로젝트 만들기` · `설치 안내` · `대시보드 보기` · `닫기` · `{이슈 제목} 보기`
- 제목 — `접근 권한이 없습니다.` · `연결할 수 없습니다.` · `첫 프로젝트를 만들어주세요.` · `스크립트를 붙여주세요.`
- 라벨 — `프로젝트 이름` · `허용 도메인`
- 본문 — `문제 인박스` · `아직 이벤트를 기다리고 있습니다.` · `첫 이벤트가 도착했습니다.` · 설치 스니펫의 `data-project-id="..."` · API 오류 메시지 통과(`invalid_allowed_domains`)
- 영역 이름 — `문제 상세`(drawer) · `핵심 지표`(지표 묶음)

## 검증

1차 게이트는 **기존 테스트가 수정 없이 통과하는 것**이다. 접근 가능한 이름을 하나라도 흘리면 여기서 걸린다.

추가로 프리미티브 단위 테스트를 소량 둔다.

- `Field` 가 힌트를 `aria-describedby` 로 잇고, 라벨 텍스트만으로 조회된다
- `Button` 이 `disabled` 와 `aria-label` 을 전달한다
- `Chip` 이 라벨 없이 호출되면 타입 에러가 난다

마지막으로 실제로 띄워 화면 4개를 눈으로 확인하고, `npm test` · `npm run typecheck` · `npm run build` 3게이트를 통과시킨다. 번들 크기는 lazy 분리 전후를 비교해 기록한다.

## 알려진 마찰 (이번 범위 밖)

- 다크 모드는 만들지 않는다. 의미값 층이 있으므로 나중에 `tokens.css` 한 곳에 블록을 더하면 된다.
- 밀도 토글은 만들지 않는다. 변수 세 개로 잡아두므로 나중에 열 수 있다.
- 린터가 없어 차트 경계 규칙을 자동 강제하지 못한다. 린터를 들이는 시점에 `no-restricted-imports` 로 옮긴다.
- 차트 종류가 늘어난 뒤에는 라이브러리 교체 비용이 배로 든다. 옮길 생각이 있다면 사용량 막대·사분면 차트가 붙기 전이 가장 싸다.
