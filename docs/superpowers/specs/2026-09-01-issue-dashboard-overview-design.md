# 문제 대시보드 개요 설계

## 목표

관리자 대시보드 첫 화면에서 문제 목록만 보지 않아도 현재 프로젝트의 위험 지점, 많이 발생하는 화면, 문제 원인, 최근 발생 문제를 함께 파악할 수 있게 한다.

## 범위

- 대상은 관리자 `DashboardPage`의 문제 인박스 화면이다.
- API, DB, SDK 수집 로직은 변경하지 않는다.
- 기존 `DashboardSummary`와 `Issue[]` 데이터만 사용한다.
- 기존 전체 문제 목록은 하단에 유지한다.

## 화면 구조

- 상단 개요: 가장 심각한 문제 1개, 점수, 심각도, 영향 세션/사용자, 추세, 최근 발견 시각을 표시한다.
- 상단 보조: 긴급/주의/낮음 분포와 신규/상승/전체 이벤트/영향 세션 지표를 표시한다.
- 중단 패널: 문제가 많은 화면, 문제 원인, 최근 발견 문제를 각각 5개까지 표시한다.
- 하단: 기존 문제 목록을 전체 목록으로 유지한다.

## 날짜 표시

- 관리자에게 노출되는 문제 발생/발견 시각은 `YYYY-MM-DD HH:mm:ss` 형태로 표시한다.
- 시간대는 기존 `formatKoreanDateTime`의 KST 변환을 사용한다.
- 최근 발견 패널에서도 시간만 표시하지 않고 연월일을 포함한다.

## 정렬과 집계

- 가장 심각한 문제는 `severityScore` 높은 순, 동점이면 `lastSeenAt` 최신 순으로 고른다.
- 최근 발견 문제는 `lastSeenAt` 최신 순으로 표시한다.
- 문제 원인은 `summary.issueTypeDistribution`을 사용한다.
- 문제가 많은 화면은 `summary.topTargets`를 사용한다.
- 상승 문제 수는 `Issue.trend === "up"` 개수로 계산한다.

## 테스트

- 새 개요 컴포넌트 테스트로 가장 심각한 문제, 심각도 분포, 최근 발견 날짜, 상위 화면/원인 표시를 검증한다.
- `DashboardPage` 테스트로 개요 섹션이 실제 대시보드에 렌더링되는지 검증한다.
